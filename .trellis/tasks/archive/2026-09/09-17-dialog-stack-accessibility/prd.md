# 修复弹窗栈与无障碍行为

## Goal

让多层 `BaseDialog` 具备可预测的顶层交互、页面滚动锁定、焦点限定与关闭后焦点恢复行为，消除子弹窗关闭时误关父弹窗或提前解除页面滚动锁的问题。

## Background

- 当前 [BaseDialog.vue](../../../frontend/src/components/common/BaseDialog.vue) 为每个弹窗独立监听 `Escape`，嵌套时多个弹窗可同时触发关闭。
- 当前任一弹窗关闭都会直接移除 `body.modal-open`，即使父弹窗仍然打开。
- `F:\sub2新站` 已有小型弹窗栈实现，但需在当前仓库中补充独立回归测试，而不依赖新站特有的账号流量组件。

## Requirements

- 在通用组件目录内维护当前打开弹窗的顺序与有效层级。
- 只允许栈顶弹窗处理 `Escape` 和 `Tab` 焦点循环。
- 弹窗栈非空时始终保留 `body.modal-open`，最后一个弹窗关闭或卸载后才移除。
- 每层弹窗获得稳定、递增的 `z-index`，同时尊重组件现有的 `zIndex` prop。
- 弹窗打开时将焦点放到首个可用交互元素；无可用元素时将焦点放到弹窗面板。
- 关闭时仅在之前的焦点元素仍连接到 DOM 时恢复焦点。
- 关闭按钮显式使用 `type="button"`，避免嵌入表单时误提交。

## Acceptance Criteria

- [ ] 嵌套弹窗打开时，按一次 `Escape` 只关闭子弹窗，父弹窗仍保持打开。
- [ ] 关闭子弹窗后，`body.modal-open` 仍然存在；父弹窗关闭后才移除。
- [ ] 栈顶弹窗中的 `Tab` 与 `Shift+Tab` 在首尾可用焦点元素之间循环。
- [ ] 无可用焦点元素的弹窗本身可获得焦点。
- [ ] 多层弹窗的计算 `z-index` 严格不下降，栈顶保持最高。
- [ ] 现有的重新打开时内容滚动位置归零测试保持通过。
- [ ] 前端相关 Vitest、typecheck 和 lint 通过。

## Out of Scope

- 不更改具体业务弹窗的布局、文案或数据请求。
- 不引入新依赖。
- 不同步新站的账号流量控制组件。
