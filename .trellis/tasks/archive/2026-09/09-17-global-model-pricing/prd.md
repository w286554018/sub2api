# 引入全局模型价格配置

## Goal

在当前 Sub2API 管理后台增加一套持久化的全局模型价格配置，使管理员可以按模型精确名称或尾部通配模式统一覆盖计费价格，同时保证未命中或未配置全局价格时，现有分组、渠道、LiteLLM 与兜底定价行为完全不变。

## Background

- 当前定价解析顺序为 `Group -> Channel -> LiteLLM -> Fallback`，入口位于 `backend/internal/service/model_pricing_resolver.go`。
- `F:\sub2新站` 已实现基础版全局价格，但不能整文件覆盖当前仓库。当前仓库额外包含 Kiro、Prompt Rules、OpenAI Responses、Astra、批量图片和更完整的媒体计费路径。
- 来源实现仅使用进程内 60 秒快照；当前仓库已有 Redis Pub/Sub 缓存失效模式，价格变更需要沿用该模式，避免多实例在改价后短暂使用不同价格。
- 当前迁移最大编号为 `237`，来源迁移 `242_global_model_pricing.sql` 必须重编号为当前仓库的下一个合法编号，不能直接复制文件名。

## Requirements

### R1. 持久化与管理 API

- 新增 `global_model_pricing` 表，保存模型模式、计费模式、token/cache 单价、按次单价、启用状态和时间戳。
- `model_pattern` 按渠道定价相同的规范化规则持久化并唯一；只允许精确名称或单个尾部 `*`，避免 `claude-3.5*` 与 `claude-3-5*` 形成运行时重复规则。
- 提供管理员列表、创建、更新、删除和启停接口。
- 写接口必须拒绝空模式、NaN/Infinity、负数、非法通配符、超长模式、token 模式缺少 input/output 价格及非 token 模式缺少按次价格。
- 价格编辑接口不修改启用状态；启停只通过独立接口完成，避免编辑与启停并发时互相覆盖。
- 所有写操作必须进入现有管理员审计中间件，并记录可定位的动作、操作者和资源 ID。
- 采用当前管理员鉴权；超级管理员权限收紧留到独立的“超级管理员”功能，不在本任务提前引入。

### R2. 定价优先级与兼容性

- 定价顺序改为 `Global -> Group -> Channel -> LiteLLM -> Fallback`。
- 精确匹配优先于通配；多个通配同时命中时，最长前缀优先。
- 匹配必须复用当前渠道定价的模型名归一化，并支持 OpenAI/Codex 变体名回落到归一化基名。
- token 模式先解析完整旧链路的有效价格，再覆盖管理员填写的全局 input/output/cache 字段；因此未填写的 cache/扩展价格保留原分组、渠道、LiteLLM 或兜底结果。
- token 模式必须填写 input/output 两项，避免私有或未知模型在没有基础价时静默按 0 结算。
- image、video、per_request 模式使用按次价格，不把隐藏的 token/cache 字段持久化。
- 无启用条目、未命中、服务不可用或缓存首次加载失败时，不得改变当前计价结果。
- 没有分组的 API Key 也必须执行全局匹配；只有 group/channel 查询依赖分组是否存在。

### R3. 全计费路径接入

- 统一 resolver 命中的全局来源必须在普通网关、OpenAI 网关、Responses、图片、视频、音频、批量图片及 token/按次结算路径中生效。
- Kiro credits 继续作为附加用量指标保存；全局价格只覆盖美元计价，不删除或替换 credits。
- Prompt Rules 继续只影响请求内容和最终 token 用量，不改变用于定价匹配的模型契约。
- 未配置 Astra 全局价格时，现有 service tier、长上下文和 cache 定价测试必须保持不变；配置后仅统一 resolver 驱动的网关结算使用全局覆盖。

### R4. 缓存一致性

- 启用价格列表使用进程内快照，避免每次请求查询数据库。
- 本实例 CRUD 后立即清空快照并重新读取。
- 复用当前 Redis Pub/Sub 模式通知其他实例清空快照；Redis 通知失败时记录告警，并由短 TTL 最终收敛，不能阻断已经成功提交的数据库写入。
- 数据库读取失败时可以短暂保留最后一次成功快照；没有历史快照时按未命中处理，保持旧定价链路。

### R5. 管理界面

- 在管理后台渠道相关导航组中增加“全局模型价格”，与 Prompt Rules、Kiro 等现有入口共存。
- 页面支持列表、刷新、新建、编辑、删除、启停，并显示匹配模式、计费模式及该模式真正生效的价格摘要。
- token 模式显示 input/output/cache 价格，单位为美元/百万 token；image、video、per_request 仅显示和编辑美元/次。
- 客户端校验与服务端规则一致，并明确说明精确匹配、最长前缀通配优先级。
- 启停和保存期间控件必须有明确禁用状态；删除确认必须展示受影响的模型模式。
- 中文和英文文案完整，复用现有 `BillingMode`、价格换算和金额格式化工具，不复制一套平行实现。

## Acceptance Criteria

- [ ] 新迁移可在空库和已有数据库上幂等执行，且不修改任何历史迁移。
- [ ] 管理 API 完成 CRUD/启停，并正确返回 400、404、409 等错误。
- [ ] 精确匹配、最长前缀匹配、大小写和 OpenAI/Codex 归一化均有自动化测试。
- [ ] 同一模型同时存在 global/group/channel 配置时使用 global；禁用或删除 global 后立即回退到原优先级。
- [ ] token 全局价格未填写的 cache/扩展字段保留旧链路有效价，不被清零；input/output 缺失会被拒绝。
- [ ] 普通网关和 OpenAI 网关的 token、image、video、按次结算均识别 global 来源。
- [ ] Kiro credits、Prompt Rules、Astra、批量图片及当前定价回归测试全部通过。
- [ ] 无分组 API Key 的普通/OpenAI token、image、video 结算仍能命中 global。
- [ ] 单实例写后立即生效；两个服务实例通过 Redis 通知后均清除旧快照；通知失败时 TTL 可最终收敛。
- [ ] 管理页面所有模式只展示并提交有效字段，非法模式和价格无法提交。
- [ ] 路由、侧栏、中英文 i18n、类型检查、lint、前后端定向测试及全量测试通过。

## Out of Scope

- 不引入阶梯价格、服务等级倍率、按分组例外或批量导入导出。
- 不修改现有分组价格与渠道价格的数据结构和编辑界面。
- 不把全局价格扩展到绕过统一 resolver 的内部展示型价格查询；本任务只保证实际网关计费链路一致。
- 不提前实现超级管理员角色、账单、工单、真实分组统计或 OpenAI 账号保护。
- 不整仓替换 `F:\sub2新站`，不删除 Kiro、Prompt Rules、OpenAI Responses 或 Astra 能力。

## Key Decisions

- 采用全局最高优先级，这是该功能“统一覆盖全部分组/账号”的核心价值。
- token 的 input/output 采用完整覆盖，cache 等扩展字段采用部分覆盖；这样兼顾未知模型安全和已有模型配置复用。
- image/video/per_request 采用单一按次价，修复来源界面显示 token 字段但实际丢弃的矛盾。
- 使用当前仓库的 Redis Pub/Sub 失效模式，而非仅照搬来源的单进程 TTL。
- 前后端随同一镜像原子发布，不额外增加长期 feature flag。

## Risks and Deferred Items

- 全局价格直接影响真实扣费，错误模式可能放大影响；通过严格校验、独立提交和完整回归矩阵控制风险。
- 金额继续沿用现有 `DOUBLE PRECISION`/`float64` 定价体系，本任务不单独迁移为 decimal，避免扩大范围。
- 多实例 Redis 通知是尽力而为；数据库仍是事实源，短 TTL 是失效通知异常时的最终一致性后备。
- 未来引入超级管理员后，应将全局价格写操作纳入敏感权限和审计策略。
- 当前版本仍允许所有现有管理员执行价格写操作；这是在超级管理员功能独立引入前的明确过渡权限边界。
